Online setup · RHEL 9 · differences from Ubuntu

Running the installer on RHEL 9

The installer targets Ubuntu. On RHEL it stops twice — at Docker Engine and at Host wiring — because it cannot provision what it needs there. Install the packages below first, then follow the Linux Online Setup Quick Guide.

2 commands · then unchanged verified on Rocky Linux 9.8 PQ installer v1.6.3

What RHEL needs that Ubuntu has

None of these ship in the RHEL 9 Minimal Install (package group @core).

WhatWhy it is needed
Docker Engine
+ compose plugin		 The installer provisions Docker through apt.
Observed: aborts at Docker Engine with apt-get: command not found
perl configure-host.sh uses it to rewrite the certificate SAN, the go2rtc ICE candidates and the Keycloak realm allowlist.
Observed: aborts at Host wiring with perl: command not found
openssl Required by generate-certificates.sh, which mints the root CA and the service certificates.
tar, gzip run.sh checks for tar and exits without it; the compose bundle is a .tar.gz.

Before you run the installer

Three steps. After them, the Linux quick guide applies.

1

Install the missing tools

sudo dnf -y install tar gzip openssl perl-interpreter
2

Install Docker Engine

From Docker's official RHEL repository:

sudo dnf -y install dnf-plugins-core sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo sudo dnf -y install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin sudo systemctl enable --now docker

Installed Docker 29.7.2 and Compose v5.5.0 on the test host.

3

Verify, then continue with the Linux guide

This should print five paths and two versions:

command -v tar gzip openssl perl docker && docker compose version

Now follow the Linux Online Setup Quick Guide from step 1. The installer detects that Docker is already present and skips its own installation step.

firewalld

The installer's firewall step understands only ufw, so on RHEL it is skipped without printing anything.

With firewalld in its default configuration this changed nothing on the test host: Docker registered its bridge interfaces in its own zone, and the front door answered while public listed no open ports.

# firewall-cmd --get-active-zones docker interfaces: docker0 br-… # firewall-cmd --list-ports (zone: public) <- empty, yet https://<host>/ answered
