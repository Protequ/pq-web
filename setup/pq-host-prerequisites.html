Part A Server sizing
§A.1 Hardware sizing
Choose the tier matching your deployment size — the same tiers apply to both Windows and Linux hosts. Each host runs ~13 containers (Postgres, Keycloak, NATS, Typesense, server, adapters, go2rtc). Part B Server host prerequisites
§B.1 Operating system
Windows · Docker Desktop / WSL2
  • Windows 11 22H2 or later recommended
  • Windows Server 2022 production deployments
  • Windows 10 build 19041+ minimum — WSL2 requires this
Linux · Docker Engine
  • Ubuntu 24.04 LTS recommended
  • Ubuntu 22.04 LTS supported
  • x86_64 (amd64) architecture required
§B.2 BIOS / Firmware — virtualization Critical
Windows · required
The installer cannot enable virtualization features. They must be turned on in firmware before it runs, otherwise WSL2 and Docker Desktop will fail to start.
  • Intel VT-x or AMD-V — enabled in BIOS/UEFI
  • SLAT / EPT / NPT support — required by Hyper-V
  • Hyper-V capable CPU most CPUs from 2015+ qualify
Linux · not required
Docker Engine runs natively on the Linux kernel — no WSL2, no Hyper-V, no BIOS/UEFI virtualization changes needed.
§B.3 Exposed ports
The installer sets up an HTTPS front door (nginx) and publishes a single web port to the host — 443 by default, configurable during install (set e.g. 8443 if 443 is already taken). Every other service — Postgres, NATS, Keycloak, Typesense, server, Monitor adapter — runs on the internal Docker network and is not exposed on the host, so no other ports need to be free. For live CCTV, WebRTC media additionally needs 8555 reachable from operator devices (RTSP 8554 stays internal).
443 8555
§B.4 Host security & anti-virus
Windows · Microsoft Defender exclusions
Real-time scanning of WSL2 virtual disks introduces significant I/O latency. Add the following paths as exclusions before installation.
%ProgramData%\Docker
%ProgramData%\Pq
%LOCALAPPDATA%\Docker
%USERPROFILE%\AppData\Local\Docker\wsl
# WSL2 vhdx files (replace <Distro> with installed distros)
%LOCALAPPDATA%\Packages\<Distro>\LocalState\ext4.vhdx
Linux · no exclusions needed
No anti-virus exclusions are required. SELinux / AppArmor in their default enforcing profiles are compatible with Docker Engine — leave them enabled.
§B.5 OS update policy
Windows · Windows Update
  • Pause Windows Update for the duration of installation prevents reboot mid-install
  • Plan a maintenance window for monthly cumulative updates Protequ services restart automatically after host reboot
Linux · unattended-upgrades
  • Pause unattended-upgrades auto-reboot for the install prevents reboot mid-install
  • Plan a maintenance window for kernel updates containers use restart: unless-stopped and the docker service is enabled, so the stack returns after reboot
§B.6 Privileges & container runtime
Windows · Administrator
The installer runs elevated. It enables Windows features (WSL, Virtual Machine Platform), installs Docker Desktop, writes to %ProgramData%\Pq, and sets ACLs on certificate stores.
Linux · root / sudo
The installer runs as root (launched with sudo). It adds Docker's official apt repository, installs docker-ce + the compose plugin, enables the docker systemd service, writes the compose stack, and opens firewall ports via ufw.
§B.7 Network & outbound access Linux online
The Linux installer is online — it cannot proceed without registry access. (The Windows installer ships an offline image bundle and needs no outbound access during install.)
  • Outbound HTTPS (443) to repo.protequ.com pulls the installer, compose bundle, and all container images
  • Outbound HTTPS to download.docker.com when Docker Engine must be installed
  • Inbound 443 + 8555 from operator devices the installer opens these via ufw if active
Part C Operator workstation
§C.1 Hardware
  • 8 GB RAM, 2 vCPU, 256 GB storage
  • Display ≥ 1920 × 1080 dual monitor recommended for the Monitor app
§C.2 OS and browser
  • Any current OS — Windows 10/11, macOS, or Linux
  • Microsoft Edge or Google Chrome — current stable version
§C.3 Network reachability
The workstation must reach the server on the front-door port — TCP 443 by default (or whatever port was chosen at install). For live CCTV also 8555 (WebRTC).
§C.4 Trust the front-door certificate
If the installer minted a self-signed CA (i.e. you did not supply your own certificate), browsers warn until each workstation trusts it once. Download ca.crt from the server, import it into the system / browser trust store, then restart the browser. In a domain, push the CA to all workstations via Group Policy. Skip if you supplied your own publicly-trusted certificate.
Appendix Pre-flight validation
§D.1 Windows — elevated PowerShell
Verifies what the installer cannot fix automatically.
# Protequ Pre-flight check — run in elevated PowerShell
$os    = Get-ComputerInfo OsName, OsBuildNumber, HyperVRequirementVirtualizationFirmwareEnabled
$ram   = [math]::Round((Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB)
$disk  = (Get-PSDrive C).Free / 1GB
$admin = ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole('Administrators')

$ports = 5432, 4222, 5443, 6443, 8108, 8443, 1984, 8554, 8555
$busy  = $ports | ? { (Test-NetConnection -ComputerName localhost -Port $_ -WarningAction SilentlyContinue).TcpTestSucceeded }

Write-Host "OS Build .........." $os.OsBuildNumber
Write-Host "VT-x enabled ......" $os.HyperVRequirementVirtualizationFirmwareEnabled
Write-Host "RAM (GB) .........." $ram
Write-Host "Free disk (GB) ...." ([math]::Round($disk))
Write-Host "Administrator ....." $admin
Write-Host "Ports in use ......" ($busy -join ', ')
§D.2 Linux — bash
Run on the Ubuntu host before installing.
#!/usr/bin/env bash
# Protequ Pre-flight check — run on the Ubuntu host
. /etc/os-release
ram=$(($(grep MemTotal /proc/meminfo | awk '{print $2}') / 1024 / 1024))
disk=$(df -BG --output=avail / | tail -1 | tr -dc '0-9')
root=$([ "$(id -u)" -eq 0 ] && echo yes || echo "no (use sudo)")
ports="443 8555 5432 4222 5443 6443 8108 8443 1984 8554"
busy=$(for p in $ports; do ss -ltn "sport = :$p" | grep -q LISTEN && echo -n "$p "; done)

echo "OS ..............." "$PRETTY_NAME ($(uname -m))"
echo "RAM (GB) ........." "$ram"
echo "Free disk (GB) ..." "$disk"
echo "Root / sudo ......" "$root"
echo "Docker ..........." "$(command -v docker >/dev/null && docker --version || echo 'not installed (installer adds it)')"
echo "Ports in use ....." "${busy:-none}"
