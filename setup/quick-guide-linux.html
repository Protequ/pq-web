Get the PQ platform running

Copy the installer to your Ubuntu server and run it. Docker Engine and every application image are installed and pulled automatically — no manual configuration.

5 steps · fully automated Ubuntu 22.04 / 24.04 LTS · 64-bit PQ Platform v1.0.0

The installer checks these automatically before it proceeds.

InternetRequired — Docker and images are pulled from repo.protequ.com during setup
PrivilegesRoot — launch the installer with sudo

Unsupported OS versions are rejected; low RAM shows a warning. Ports 443 and 8555 must be reachable from operator devices.

Installation

Five steps, start to finish. Most of it runs on its own.

1

Download & run the installer

Distribution is admin-mediated, like the Windows installer. Signed in to repo.protequ.com, download the single artifact pq-installer-online-v<version>-linux-x86_64.tar.gz from the pq-installer package, copy it to the server, then unpack and run as root:

tar xzf pq-installer-online-v*-linux-x86_64.tar.gz sudo ./run.sh

Run as root.

The installer enables the Docker service, writes the compose stack to /opt/pq, and opens firewall ports — all of which require root. run.sh uses the binary + bundle next to it (no public download).

2

Preflight & Docker Engine

The installer checks the OS, RAM, architecture, and busy ports. If Docker Engine is missing it adds Docker’s official apt repository, installs docker-ce and the compose plugin, and enables the docker service. No reboot is required.

3

Network access

Answer how operator devices reach this host. The detected hostname / LAN IP is offered as the default — press Enter to accept or type your own.

Host name or IP — clients open https://<host>/.

Port — defaults to 443; set e.g. 8443 if 443 is taken.

Additional names / IPs — extra SANs added to the certificate and login allowlist. Recommended: add the server's IP address here, so the certificate is valid when clients connect by IP (not only by hostname).

Own TLS certificate — optionally supply your own cert + key instead of the auto-generated one.

4

5

Done!

The installer prints the URL. Verify the stack and open the UI:

docker compose -f /opt/pq/compose/docker-compose.yml ps

Open https://<host>:<port>/ in a browser and log in.

The browser shows a one-time certificate warning (self-signed) — click Advanced → Proceed to get in. To remove it permanently, see Trust the certificate below.

Default loginadmin / admin

Trust the certificate

The front door uses a self-signed CA, so browsers warn until each operator workstation trusts it once. Skip this if you supplied your own publicly-trusted certificate during setup.

1 — Download the CA from the server (accept the one-time browser warning, or use curl):

curl.exe -k https://<host>:<port>/ca.crt -o "%USERPROFILE%\Downloads\pq-root-ca.crt"

2 — Import it into “Trusted Root Certification Authorities” — either option works:

• Right-click / double-click pq-root-ca.crt → Install Certificate → Local Machine → Place all certificates in the following store → Trusted Root Certification Authorities → Finish.

• or PowerShell (as Administrator):

Import-Certificate -FilePath "$env:USERPROFILE\Downloads\pq-root-ca.crt" -CertStoreLocation Cert:\LocalMachine\Root

3 — Restart the browser. https://<host>:<port>/ is now trusted (green padlock).

In a domain, push the CA to all workstations via Group Policy instead of importing per machine. macOS/Linux clients import the same ca.crt into their system / browser trust store.

Troubleshooting

Common issues and how to resolve them.

ProblemSolution
“System requirements not met”Use Ubuntu 22.04 or 24.04 LTS on a 64-bit (amd64) host
Port already in useFree the reported port, or set a different front-door port in Step 3
Docker daemon not runningsudo systemctl start docker, then re-run the installer
Cannot reach the UI from another deviceOpen 443 + 8555 in the firewall (the installer does this when ufw is active)
Containers fail to startRe-run the installer — it is idempotent and resumes
Certificate error in browserExpected (self-signed) — Advanced → Proceed, or trust the CA (see Trust the certificate)
Logs— streamed by the installer; container logs viadocker compose logs
Config files—/opt/pq/compose/
